**Realmaze** is a first-person escape game built with Unity 6. Explore a realistic outdoor maze, collect the coins needed to open the chest, recover the key, unlock the gates, avoid hostile zombies, and reach the escape zone.

**Play the browser build:** https://masterchiefproject.github.io/Realmaze/

> The browser build intentionally uses a much lower visual preset than the Unity Editor version. The goal is reliable startup and smooth play on ordinary desktop browsers while preserving the original game logic, scenes, and environment.

## Gameplay

A run starts from `MainMenuScene` and loads the main `GameScene`.

Your objective is to:

1. Explore the maze and collect coins.
2. Reach 20 coins to open the chest.
3. Take the revealed key.
4. Use the key to unlock the gates.
5. Avoid zombies and other hazards.
6. Reach the escape zone.

The project includes collectible state, gated progression, enemy patrol behavior, death/restart handling, and a victory flow.

## Browser performance profile

The WebGL deployment intentionally trades visual fidelity for reliable browser startup and stable frame time.

The production build uses Gzip compression with decompression fallback for GitHub Pages, browser data caching, WebAssembly 2023, no WebGL threads, no debug symbols, size-oriented IL2CPP generation, managed-code stripping, and engine stripping.

During the WebGL build, every quality level is temporarily switched to the project's existing `Mobile_RPAsset`. The two highest eligible texture mip levels are excluded through Unity mip stripping. This reduces texture download, decompression, GPU upload, memory use, and unnecessary PC URP shader variants. The original Editor quality configuration is restored after the build.

The menu uses asynchronous scene loading in WebGL so `GameScene` deserialization is distributed over frames rather than forcing the normal synchronous transition.

At runtime, the Web-only performance bootstrap:

- renders at a fixed `960 × 540` internal canvas with device pixel ratio `1`
- disables real-time shadows, MSAA, anisotropic filtering, reflection probes, HDR, and post-processing volumes
- limits the camera far clip distance to 100 meters
- lowers terrain detail, tree, billboard, and basemap distances
- limits asynchronous texture/mesh upload work to a small per-frame time slice
- uses a two-level texture mip limit

The zombie patrol implementation is also optimized for the browser build. Its collision avoidance uses a reusable `Physics.OverlapSphereNonAlloc` buffer instead of allocating an array every frame, caches the active terrain, and samples local avoidance at staggered intervals in WebGL.

These runtime changes are compiled only for WebGL where applicable. Running the project normally inside the Unity Editor preserves the original high-quality presentation.

A true reduction in scene deserialization memory would require splitting `GameScene` into additive/streamed chunks or Addressables. That is deliberately not done automatically because it changes scene architecture and needs gameplay-aware authoring.

## Run in the Unity Editor

Use Unity `6000.0.47f1`.

If this is a fresh clone, pull Git LFS assets first:

```powershell
git lfs install
git lfs pull
```

Open:

```text
Assets/Scenes/MainMenuScene.unity
```

Press **Play**, then select **Start**. This verifies the complete production flow from the menu into `GameScene`.

You can also open `Assets/Scenes/GameScene.unity` directly for gameplay iteration.

## Build for GitHub Pages

Do not manually recreate the WebGL profile each time.

From Unity, use:

```text
Realmaze > Build WebGL for GitHub Pages
```

The command:

- switches to the WebGL target if required
- builds exactly the two production scenes
- applies production metadata (`MasterChiefProject`, `Realmaze`, `1.0.0`)
- applies the browser-performance profile only for the duration of the build
- builds into the ignored `Builds/RealmazeWebGLStaging/` staging directory
- replaces `docs/` only after a successful build
- writes `docs/.nojekyll`
- restores the original quality settings afterward

It does not use `CleanBuildCache`, so keeping the local `Library/` directory allows Unity to reuse its normal build/import caches.

Test the generated site with a local HTTP server:

```powershell
py -m http.server 8000 --directory docs
```

Then open:

```text
http://localhost:8000/
```

Do not open `docs/index.html` directly with `file://`. Unity Web builds must be served over HTTP.

## Repository checks

The repository includes lightweight automated checks that do not require a Unity license on GitHub Actions.

Run them locally with:

```powershell
node --test tests/*.test.mjs
node --check Assets\WebGLTemplates\Realmaze\TemplateData\shell.js
```

The checks validate the Unity version, production scenes, WebGL build policy, production metadata, low-resolution web shell, theme persistence, WebGL-only performance bootstrap, gate physics safeguards, and known gameplay/source invariants.

Unity Editor compilation and a Play Mode smoke test remain the final validation for game behavior.

## Large assets and Git LFS

This repository uses Git LFS for several Unity asset types. A normal clone that has not downloaded its LFS objects can appear to have missing or invalid textures and project assets.

Use:

```powershell
git lfs install
git lfs pull
```

before opening a fresh clone in Unity.

Do not commit generated Unity directories such as `Library/`, `Temp/`, `Logs/`, or `obj/`.
